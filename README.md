# QNX sample project for CLion

A small QNX Neutrino application for demonstrating how to configure, build, run
and debug a QNX Makefile project in CLion.

The program reports the context it was started in — the path it was loaded
from, its working directory, its arguments and optionally its environment.

It also contains a bug, left in deliberately to demonstrate AI-assisted
debugging in CLion. Given `a b c d` or more — five arguments counting
`argv[0]` — it dies with SIGSEGV part way through the output. 

## Layout

```
Makefile          LIST=OS, generated by addvariant
common.mk         shared build rules and build options
main.c            banner, path, cwd, arguments, environment
argstats.c/.h     argument length statistics — holds the deliberate bug
qnx-sample.use    usage message, embedded by usemsg
nto/x86_64/o      optimised   -> qnx-sample        nto/x86_64/o-g      debug -> qnx-sample_g
nto/aarch64/o.le  optimised   -> qnx-sample        nto/aarch64/o.le-g  debug -> qnx-sample_g
```

<details>
<summary><b>Presenter notes — spoilers</b></summary>

`argstats.c` keeps per-argument lengths in a fixed array and the guard is off
by one:

```c
if (i <= ARGSTATS_MAX) {   /* should be < */
    stats->lengths[i] = len;
}
```

`lengths[ARGSTATS_MAX]` lands exactly on the `longest` pointer (offset 32).
With `argc >= 5` the loop reaches `i == 4` and writes that argument's length
over it. The write stays inside the struct, so the stack protector never fires
and nothing complains until `argstats_report()` dereferences it.

The fix is one character:
`i < ARGSTATS_MAX`

</details>
